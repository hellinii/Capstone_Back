# 심판 기준 묶음 변경 기록

기준 묶음(이 폴더)은 심판이 무엇을 어떻게 재는지 정하는 파일 전부다: 체크리스트, 주장 규칙, 모순 유형, 표기 규칙, 모델 설정,
프롬프트, 작은 코드 규칙. 검증(설계 7절)은 고정한 버전 하나에 대해 하고, 고정 뒤에 하나라도 바꾸면 버전을 올리고 다시 검증한다
(설계 7.4·7.5). 지문은 `MANIFEST.sha256`(파일마다 sha256), 버전 → 지문 기록은 `VERSIONS.json`(덧붙이기만)이다.
`VERSIONS.json`·이 파일·`MANIFEST.sha256` 자신은 지문에 들지 않는다.

## 1.0-dev

- 심판 라운드 J1(2026-10-29): 뼈대 — 모델 설정(`model.json`). 기준 고정(V1) 전까지 이 이름으로 고친다. 고정할 때 VERSION 을
  "1.0" 으로 바꾸고 `VERSIONS.json` 에 그 지문을 처음 적는다.
- 심판 라운드 J4 파일럿(2026-10-29, 개발 입력 dev_binary 규칙 문장 서술)으로 고침 — 규칙 문장은 데이터로 만든 글인데 발급 불가가
  나왔다(사실 위반 4·단정형 추론 12·값 불일치 1). 모두 심판 쪽 오탐이었다.
  - 사실 일치: 추출이 붙인 칸과 맞을 때만 코드가 바로 확정하고, 어긋나면 에이전트가 대상을 다시 찾는다(칸 잘못 짚기).
  - 숫자 규칙: 부호 없이 쓴 숫자는 크기로도 본다(방향을 말로 쓴 차이). 이름: 판정 코드 ↔ 찍히는 이름 표(names.json), 가장 긴 이름으로.
  - 주장 규칙: 추론 표시는 어간으로(수 있·가능성·위험이 있 등), 권고의 기대 효과·일반 원리 설명은 주장이 아니다.
  - 일관성: 서술 숫자가 다른 칸 데이터 값과 맞으면 칸 잘못 짚기로 보고 세지 않는다(따로 적음).
  - 표기: '%p' 단위, 문제 번호(P1)·참조 기준 출처 글 낱말 허용, 문장 끝 괄호 설명을 걷고 해라체를 본다. 어법은 LLM(검사기 메모리).
  - 전처리(주장 추출) 추론 강도 low(model.json extract_effort) — 판단 없는 옮기기라. 심판 4모듈은 medium 그대로.
