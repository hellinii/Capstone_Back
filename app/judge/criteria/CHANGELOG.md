# 심판 기준 묶음 변경 기록

기준 묶음(이 폴더)은 심판이 무엇을 어떻게 재는지 정하는 파일 전부다: 체크리스트, 주장 규칙, 모순 유형, 표기 규칙, 모델 설정,
프롬프트, 작은 코드 규칙. 검증(설계 7절)은 고정한 버전 하나에 대해 하고, 고정 뒤에 하나라도 바꾸면 버전을 올리고 다시 검증한다
(설계 7.4·7.5). 지문은 `MANIFEST.sha256`(파일마다 sha256), 버전 → 지문 기록은 `VERSIONS.json`(덧붙이기만)이다.
`VERSIONS.json`·이 파일·`MANIFEST.sha256` 자신은 지문에 들지 않는다.

## 1.0-dev

- 심판 라운드 J1(2026-10-29): 뼈대 — 모델 설정(`model.json`). 기준 고정(V1) 전까지 이 이름으로 고친다. 고정할 때 VERSION 을
  "1.0" 으로 바꾸고 `VERSIONS.json` 에 그 지문을 처음 적는다.
- 심판 라운드 J4 파일럿(2026-10-29, 개발 입력 dev_binary 규칙 문장 서술)으로 고침 — 규칙 문장은 데이터로 만든 글인데 발급 불가가
  나왔다(사실 위반 4·단정형 추론 12·값 불일치 1). 모두 심판 쪽 오탐이었다.
  - 사실 일치: 추출이 붙인 칸과 맞을 때만 코드가 바로 확정하고, 어긋나면 에이전트가 대상을 다시 찾는다(칸 잘못 짚기).
  - 숫자 규칙: 부호 없이 쓴 숫자는 크기로도 본다(방향을 말로 쓴 차이). 이름: 판정 코드 ↔ 찍히는 이름 표(names.json), 가장 긴 이름으로.
  - 주장 규칙: 추론 표시는 어간으로(수 있·가능성·위험이 있 등), 권고의 기대 효과·일반 원리 설명은 주장이 아니다.
  - 일관성: 서술 숫자가 다른 칸 데이터 값과 맞으면 칸 잘못 짚기로 보고 세지 않는다(따로 적음).
  - 표기: '%p' 단위, 문제 번호(P1)·참조 기준 출처 글 낱말 허용, 문장 끝 괄호 설명을 걷고 해라체를 본다. 어법은 LLM(검사기 메모리).
  - 전처리(주장 추출) 추론 강도 low(model.json extract_effort) — 판단 없는 옮기기라. 심판 4모듈은 medium 그대로.
  - 2차 파일럿 뒤: 판정 규칙 기준값을 조회 자료에(rule_constants.json), '같다'는 셋째 자리 반 칸 안, 이름 끝 문장부호 무시,
    지표 성능이 아닌 크기 표현(치우침·불균형)은 정도 표현 대상 불명.
  - 3차 파일럿 앞: 규범 어미(…해야 한다 등)가 든 추론은 코드가 버림(normative_markers), 고객 입력 칸은 일부 인용도 일치,
    같은 양 비교에서 한쪽만 부호면 크기로.
  - 사실 시트의 숫자 글 칸(*_text)도 숫자 조회 자료로(코드 sources.py — 기준 묶음 밖이지만 판정에 닿아 여기 적는다).
  - AI 파일럿 뒤: 시험 범위 문장(…하지 않았다 등)은 추론이 아님(scope_markers, 코드가 버림), 고객 입력 다시 말하기(참고 글 떼고
    두 글자 묶음 60%), 양성 클래스 ↔ '양성', 선언은 facts.declarations 칸 먼저, '…ㅂ니다'만 합니다체('아니다' 아님).
- 심판 라운드 J4 끝(2026-10-29): **주장 규칙 잠금** — claims.json sha256 2fd85afecccda1bea6a3d3270c55c1068e06ab589915b7457e5d546cb6403a65. 사람 정답지 표시는 이 규칙으로 한다
  (바꾸면 표시를 다시 — tests/test_judge_criteria_manifest.py CLAIMS_LOCK).

    모델 설정(`model.json` — 심판·추출 모델, 추론 강도), 프롬프트 6개(`prompts/` — 추출·추출 자기 점검·사실 일치·일관성·
    필수 내용·표기), 작은 코드 규칙 4개(`rules_*.py`), 로더(`__init__.py`), `VERSION`.
  - 주장 규칙은 J4 끝에 먼저 잠갔다(위 1.0-dev 절의 claims.json sha256). 1.0 의 claims.json 은 그 값 그대로다 — 사람 정답지
    표시가 이 규칙으로 되어 있다.
  - 왜: 검증 V2(설계 7절)는 고정한 버전 하나에 대해 한다. V2 의 모든 회차가 이 기준(1.0)으로 돌고, 검증을 통과하면 검증 기록
    (validated.json)이 이 버전·지문을 적어 판 4 잠금을 연다.
  - 다음: 1.0 뒤에 위 파일을 하나라도 바꾸면(프롬프트 한 글자, 모델 설정 포함) 시험이 빨개진다. 그때는 버전을 올리고(1.1 등)
    이 파일에 새 절로 이유를 적은 뒤 다시 고정하고 다시 검증한다(설계 7.4·7.5). `VERSIONS.json` 의 1.0 줄은 지우거나 고치지
    않는다(덧붙이기만).

  (2026-10-31). 시험은 봉인 서술이 아니라 지어낸 문장으로 한다(오염 방지 규칙 2).
  1. 한글 선언 ↔ 코드값: 이름 표(`names.json`)에 의뢰자 선언 코드값 전부(risk_direction fn·fp·similar, class_priority
     all_equal·larger_first·samples_first, usage_mode batch·realtime)의 찍히는 이름과 흔한 바꿔 말하기를 더했다('배치 방식'↔batch,
     '거짓 음성'↔fn, '모든 레이블이 동등'↔all_equal 이 위반이었다). 고객 선택지 바꿔 말하기 표(`client_option_labels` — '같은 출처'↔
     '같은 조건')도 더했다. 반대 값('다른 …')의 말이 같이 있으면 맞지 않다.
  2. 비율의 분모: 칸 설명 표(`field_notes.json`, 새 파일)를 칸 목록과 조회 답에 싣는다 — `facts.error_totals.total` 은 전체 표본
     수이지 오류 건수가 아니다('전체 오류 3건의 33.3%' 를 전체 표본 171 로 나눠 0.006 이 됐다). 클래스별 표본 비율 칸
     `distribution.class_share.<클래스>`(건수 ÷ 평가 샘플 수)을 코드가 만든다(sources.py — 기준 묶음 밖이지만 판정에 닿는다; '107건
     (62.6%)' 의 백분율을 건수 칸과 대조했다). 숫자 규칙(`rules_numbers.py`)이 분수 말 'N분의 M' 을 몫으로 읽는다('3분의 1').
  3. 비교를 숫자 하나로: 숫자 주장이라도 에이전트가 두 식과 관계를 주면 비교로 대조한다(faithfulness.py). 문장에서 수량을 찾을 때
     이름에 붙은 숫자('클래스 3'·'레이블 14')는 건너뛴다(`rules_numbers.NAME_BEFORE_NUMBER`) — 수량이 없으면 위반이 아니라 검증 불가다.
  4. 사실·판정 옮김을 추론 단정으로: (가) 표시 낱말 보탬(`inference_rules.json`, 새 파일 — claims.json 은 사람 정답지 규칙이라
     그대로 두고 코드가 두 목록을 합친다): 추론 표시 '기 쉽'·'기 쉬', 규범 '야 한다·야 하며·야 하고', 범위 '단정할 수 없·단정하기
     어렵·알 수 없·판단할 수 없'. 모두 claims.json not_claims 줄이 이미 말하는 것의 어미다. (나) 사실 일치 에이전트가 추론 주장을
     세 갈래로 답한다(`prompts/faithfulness.md`): ① 데이터·판정·고객 입력을 옮긴 문장이면 비교·이름 대조로 옮기고 코드가 대조한다
     (맞으면 match, 틀리면 violation — 대조할 칸이 없으면 어미 판정으로 돌아감), ② 용어 뜻풀이·일반 원리 설명이면 not_claim(새 판정
     — 분모·게이트 밖, 기록 counts.not_claim), ③ 그 밖은 지금처럼 어미로. 애매하면 ③. 맞다·틀리다는 여전히 코드가 정한다.
  5. 일관성 값 묶기: 칸 값이 비율(0~1)인데 서술 숫자가 백분율도 아닌 1보다 큰 수면 그 칸의 표기일 수 없어 칸 잘못 짚기로 본다
     (consistency.py — '2,000회' 를 신뢰수준 칸에 붙여 '95%' 와 모순으로 셌다). J4 의 "어느 데이터와도 안 맞는 숫자는 센다"는 그대로다.
  - 지난 5회 기록(추출 주장·에이전트 답)을 새 코드로 다시 판정하면(실호출 없음) 코드 쪽 고침(1·2 분수·3 이름 숫자·4 가·5)만으로
    27건 가운데 13건이 풀린다. 나머지(분모 칸 고르기, 옮긴 추론, 뜻풀이)는 에이전트가 새로 답해야 해서 다시 검증에서 본다.
  - 재검증 범위표(validation/rescope.py)에 새 파일 두 줄(추출·사실 일치).
- 독립 검토 반영(2026-10-31, P0 0·P1 6·P2 7) — "에이전트가 답하는 꼴만 바꿔도 맞다·틀리다가 바뀐다"는 구멍을 막았다.
  - 숫자 주장을 비교로 답해도 문장에 수량이 있으면 그 숫자가 앞쪽 식 값과 맞아야 match('150건으로 실제보다 많다' ↔ 130).
  - 추론을 데이터 대조로 옮기는 것은 문장에 인과 낱말(`inference_rules.json` causal_markers — 때문·원인·로 인해 등)이 없을
    때만. not_claim 은 코드가 확인한다 — 뜻풀이 어미(definition_markers — 뜻한다·의미한다·를 말한다)가 있고 숫자·인과 낱말이
    없을 때만, 아니면 어미 판정. 프롬프트 ②를 뜻풀이로 좁힘('일반 원리 설명' 뺌).
  - 이름 대조(`names.json` code_groups·negation_after): 실제 값이 든 묶음(판정·위험 방향·클래스 중요도·사용 방식)의 이름만
    본다. 더 긴 이름 자리에 덮인 짧은 자리는 뺀다. 같은 묶음 두 코드가 다 지목되면 검증 불가('FN 이 FP 보다' — 1.0 부터 코드
    글자 순서로 맞다였다). 이름 바로 뒤 6자 안에 부정(아니·아닌·않·없)이 오면 지목이 아니고, 실제 값을 부정하면 위반. 짧은
    이름 '동등하다' 뺌. 고객 선택지는 반대 값의 말이 있으면 글 겹침 대조로 넘기지 않는다(둘 다면 검증 불가, 반대만이면 위반).
  - 일관성 비율 칸 규칙은 정수가 아닌 0~1 값 칸에만(건수 칸 0·1 의 진짜 모순을 숨겼다).

  - 이름 뒤 숫자라도 '개·종·가지'가 붙으면 수량. 점수표에 not_claim·from_inference(추론에서 옮겨 checked 에 든 수).

    27건 중 13건 풀림.
  - 기준 지문 밖이지만 판정에 닿는 코드(faithfulness.py·consistency.py·extract.py·sources.py·aggregate.py)는 1.1 고정 커밋에
